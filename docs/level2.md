# 盘口 / L2（五档盘口 · 逐笔成交 · 资金流）

> 这一页解决三件事：**能白拿什么、拿不到什么、想要更多怎么接**。
> 结论先说：免费公开源可以给你「五档盘口 + 逐笔成交 + 由逐笔自算的资金流」，
> **拿不到**十档行情、逐笔委托、委托队列——它们需要交易所授权、由持牌厂商付费分发。

---

## 1. 能力边界（务必先读）

| 能力 | 本项目的状态 | 来源与说明 |
|---|---|---|
| 五档盘口（买卖各 5 档量价） | ✅ 可用 | 腾讯 `qt.gtimg.cn`、新浪 `hq.sinajs.cn` 等公开快照接口 |
| 逐笔成交（含第三方盘口方向标记 B/S/M） | ✅ 可用 | 腾讯 `stock.gtimg.cn/...?appn=detail`，约覆盖最近 **4000 笔**（分页） |
| 主力资金流（超大单/大单/中单/小单） | ✅ 可用 | **不依赖任何「主力资金」接口**，由逐笔按单笔成交额分档自算（见 §2.3） |
| 外盘 / 内盘（主动买 / 主动卖手数） | ✅ 可用（腾讯） | 快照字段，可与逐笔口径交叉参考 |
| **十档行情** | ❌ 需付费授权 | 交易所 Level-2 数据，经券商 / 迅投 QMT / Wind / 同花顺 Level-2 等分发 |
| **逐笔委托 / 委托队列（挂单排队）** | ❌ 需付费授权 | 同上 |
| 同花顺客户端内的 Level-2 数据流 | ❌ 不做 | 逆向其加密协议违反服务协议与相关法律，也与本项目「零依赖、仅研究」原则冲突 |

**合规底线**：本项目只使用各站点**公开网页接口**（与已有的腾讯/新浪/东财源同一性质），
不逆向任何付费客户端、不绕过付费墙、不缓存或分发受限行情数据；仍然**只做模拟盘**，永不触达真实券商。

## 2. 数据口径（决定了数字为什么长这样）

### 2.1 五档盘口的单位

| 源 | 档位数量单位 | 处理方式 |
|---|---|---|
| 腾讯 | **手** | 直接使用；金额 = 价格 × 手数 × 100 |
| 新浪 | **股** | 统一换算成手（不足 1 手按 1 手），金额按股数如实计算 |

> 同一个价位在两个源上的量可能不同（快照时点不同、以及上述单位差异），这是正常的；
> 界面上会标明当前 `source`。

### 2.2 逐笔成交的方向标记

腾讯逐笔字段为 `序号/时间/价格/涨跌/手数/金额/方向`，方向取值 `B` / `S` / `M`。
**它是第三方标注的「盘口方向」**，不是交易所 Level-2 的主动/被动成交判定，
也不要与「外盘/内盘」完全等同——两者口径不同，请交叉参考而不是互相替换。

### 2.3 资金流分档口径

按**单笔成交额**分档（与东财公开口径一致）：

| 档位 | 阈值 |
|---|---|
| 超大单 | ≥ 100 万元 |
| 大单 | 20 万 ~ 100 万元 |
| 中单 | 5 万 ~ 20 万元 |
| 小单 | < 5 万元 |

- 每档分别累计买入额（`side=buy`）与卖出额（`side=sell`），`净额 = 买入 − 卖出`；`M`（中性）计额但不计入买卖方向；
- **主力净额 = 超大单净额 + 大单净额**；`主力净额占比 = 主力净额 / 样本成交额 × 100%`；
- 样本 = 拉取到的逐笔（默认最多 2000 笔，可调）；若源未给单笔金额，则用 `价格 × 手数 × 100` 估算。

派生指标（五档）：委买量 / 委卖量、委比 `=(委买−委卖)/(委买+委卖)×100%`、委差、价差 `=卖一−买一`、中间价。

### 2.4 覆盖范围与刷新

- 盘口是**快照**：服务层缓存 2 秒，界面自动刷新（默认关闭，开启后 3 秒一次）；
- 逐笔缓存 10 秒；逐笔总量受源限制（约 4000 笔），因此「主力资金流」是**当日至今的近似**，不是全天精确值。

## 3. 怎么用

### 3.1 桌面版 / Web 版

两个界面同一套口径：

1. 输入代码（`600519.SH` 或 `600519`）→「查询」；
2. 指标卡：现价、涨跌幅、**委比、委差**、外盘、内盘；
3. **五档表**：卖 5 → 卖 1 → 买 1 → 买 5（卖绿买红）；
4. **逐笔表**：时间 / 价格 / 手数 / 金额 / 方向（最多 60 行）；
5. **资金流卡**：四档净额与买入占比、主力净额与占比；
6. 页面固定提示：「五档为公开源快照，逐笔方向为第三方盘口标记（非交易所 Level-2）；十档/委托队列需付费授权」。

离线模式（`QUANTSTUDIO_OFFLINE=1`）下页面显示内联空状态并说明原因，不会发起网络请求。

### 3.2 HTTP 接口

```
GET /api/level2/<code>/orderbook          # 五档 + 派生指标 + 能力协商
GET /api/level2/<code>/ticks?limit=120    # 逐笔（升序，含多空统计）
GET /api/level2/<code>/flow?limit=2000    # 分档资金流
```

### 3.3 MCP 工具（给大模型）

| 工具 | 作用 |
|---|---|
| `level2_orderbook` | 五档盘口与委比/委差/价差（含能力协商字段） |
| `level2_ticks` | 最近逐笔成交 + 多空统计（默认 60 条，文本里注明覆盖上限与方向口径） |
| `capital_flow` | 四档资金流与主力净额（自算口径） |

### 3.4 L2 工具箱（桌面 / Web 同一套，共 5 个）

| 工具 | 作用 | 关键口径 |
|---|---|---|
| **大单追踪** | 逐笔里**单笔金额 ≥ 阈值**（20 万 / 50 万 / 100 万 / 200 万，默认 100 万）的成交，时间倒序，附笔数、买卖额、净额、占样本成交额比、最大单笔 | 阈值即分档线（≥100 万 = 超大单）；样本约最近 4000 笔 |
| **资金流分时** | 逐笔按**分钟**聚合：每分钟主动买/卖/净额 + **累计净额曲线**，以及四档分档净额 | 方向取第三方盘口标记；累计净额 = 各分钟净额累加 |
| **封板状态** | 此刻是否涨停/跌停、涨停价、距涨停 %、**封单量/封单额/封成比** | 涨跌停幅度按板块推断（主板 10% / 创业板·科创板 20%（含 689）/ 北交所 30%；**ST 为 5%，需自行核对**），涨停价按**四舍五入到分**（A 股口径，不是银行家舍入）；只按当前快照判断，**不给开板次数** |
| **盘口异动扫描** | 对一组标的（缺省=自选池，最多 10 只）取快照，按**委比**降序给出涨跌幅、委买委卖量、比值、量比、封板与距涨停 | 单次快照的静态特征；「挂单骤增 / 大单撤单」这类**突变检测需要两次以上采样**，不承诺 |
| **资金流排行** | 对一组标的（缺省=自选池，最多 10 只）算主力净额与占比，按主力净额降序 | 每只要拉一次逐笔，**约 10–25 秒/只**；主力净额 = 超大单 + 大单 |

**对应的 HTTP 接口**（Web / 脚本可直接用）：

| 接口 | 说明 |
|---|---|
| `GET /api/level2/<code>/big-orders?threshold=1000000&limit=50` | 大单追踪（可选 `sides=buy` / `sides=sell`） |
| `GET /api/level2/<code>/flow-series?limit=2000` | 资金流分时序列 |
| `GET /api/level2/<code>/seal` | 封板状态 |
| `GET /api/level2/scan?codes=A,B,C&limit=10` | 盘口异动扫描（`codes` 缺省=自选池） |
| `GET /api/level2/flow-rank?codes=A,B,C&top=10&limit=1000` | 资金流排行（`codes` 缺省=自选池） |

**对应的 MCP 工具**：`l2_big_orders`、`l2_flow_series`、`l2_seal_status`、`l2_scan`、`l2_flow_rank`
（`structuredContent` 返回上面的完整结构；文本只给精简摘要，避免灌满上下文）。

> **耗时提示**：大单 / 分时约 3–10 秒；扫描约 1 秒/只；排行约 10–25 秒/只（10 只时可能 2–4 分钟）。
> 界面上这四个工具都走后台任务并有「进行中」提示，**不参与 3 秒自动刷新**（自动刷新只覆盖盘口/逐笔）。


## 4. 接入真正的 Level-2（你有付费权限时）

本项目**不提供**任何厂商适配器，但把接口位留好了，两条路：

### 4.1 写一个 Provider（推荐给有行情 API 的人）

在 `backend/quantstudio/data/` 下新增一个 Provider（照 `tencent.py` 的 `BaseHTTPProvider` 写法），实现：

```python
class MyL2Provider(BaseHTTPProvider):
    name = "my_l2"
    ORDERBOOK_LEVELS = 10          # 声明档数（capabilities 会读它）
    LEVEL2_IMPORT = False

    def orderbook(self, code):     # -> OrderBook（十档填满 bids/asks，levels=10）
        ...
    def ticks(self, code, limit=600):   # -> List[Tick]
        ...
    def order_events(self, code, limit=600):   # 可选：逐笔委托
        ...
    def order_queue(self, code):               # 可选：委托队列
        ...
```

然后把它接进降级链（`data/composite.py` 的 `_build_providers` 与 `CHAIN_PRIORITY`）。
`data.level2.capabilities(provider)` 会自动报告 `orderbook_levels / orders / queue`，
界面与 MCP 的「能力协商」字段随之变化。

### 4.2 本地文件导入（推荐给只能用客户端导出的人）

把导出的 CSV 放到 `QUANTSTUDIO_LEVEL2_DIR`（默认 `<data_dir>/level2`）下，命名（代码写法
`600519.SH` / `600519` / `sh600519` / `600519-SH` 均可，`-`/`_`/空格与 `.` 等价）：

```
<code>.orderbook.csv     # 例如 600519.SH.orderbook.csv
<code>.ticks.csv         # 例如 600519.SH.ticks.csv
```

**通用规则**：列名大小写不敏感、可带表头也可不带（不带则按下面列序取）、列序可换；
编码 UTF-8（含 BOM）或 GBK/GB18030；空行与 `#` 注释行忽略；坏行（列数不足 / 非法数字 / 非法枚举）跳过；
解析绝不抛异常——文件缺失或无有效行时该源报「不可用」，其它源照常降级。

**盘口文件**（列 `side,level,price,volume[,amount]`）：

```
side,level,price,volume,amount
bid,1,1237.00,13,1608100
bid,2,1236.95,4,494780
ask,1,1237.05,1,123705
ask,2,1237.50,1,123750
```

- `side`：`bid`（买）或 `ask`（卖）；`level`：从 1 开始（1 = 买一/卖一），可到 10；
- `volume` 单位**手**；`amount` 可省略（省略时按 `价格 × 手数 × 100` 估算）。

**逐笔文件**：

```
time,price,volume,amount,side
09:30:01,1237.00,13,1608100,buy
09:30:02,1237.05,4,494780,sell
```

- `time`：`HH:MM:SS`（也接受 `HH:MM` 或 `YYYY-MM-DD HH:MM:SS`，只取时间部分）；`volume` 单位**手**；
  `amount` 可省略（按 `价格 × 手数 × 100` 估算）；`side` 可省略，取 `buy`/`sell`/`neutral`
  （也兼容 `B`/`S`/`M`），缺省 `neutral`；行序保持文件顺序。

导入后的数据与免费源产物是**同一套模型**（`OrderBook` / `Tick`），因此盘口页、资金流、MCP 工具
都能直接消费；坏行/缺列会被跳过，文件缺失时该源报「不可用」，不会影响其它源。


**优先级**：在线的默认链路是「腾讯 → 新浪 → 本地文件 → 磁盘缓存 → CSV → 示例」，
也就是**公开源优先、你的文件兜底**（实时性优先，且没有文件时不会产生任何噪音）。
想让自己的 Level-2 文件**直接生效**（纯本地、不走网络），设 `QUANTSTUDIO_OFFLINE=1`
再打开盘口页即可；界面的「能力协商」会显示 `10 档 / 导入可用`。
> 自己导出的数据请遵守你与数据提供方的协议：**不要**把受限行情提交进本仓库或再分发。
